# Plan 35 follow-up: mana regeneration and a stable relog

Issue #137. The level-1 Human Mage casts Fireball at a **neutral** training dummy, so it never enters
combat: mana comes back on its own, `/logout` is accepted, and the same character re-enters the world and
casts again. Full logs, screenshots and the packet capture stay in the run directory
(`/mnt/f79365ff-6a68-45da-925e-b9ddc6d5da6c/cata-runs/plan35b-mage/`).

## Pins

- Client build **15595**; reference TrinityCore `c699217775d90794158422387b07a917e161b582`.
- Branch `plan/35b-mana-combat-regen-relog`; generation 1, binaries `5289b5fe4`, harness `005900286`
  (the prepared config was regenerated by the same code path as `prepare`).
- Character: level-1 **Human Mage** (race 1 / class 8) from the native creation flow, Fireball **133** on
  action button 0.
- Target: **Advanced Training Dummy, entry 24792**, faction 7 (neutral), level 80 with a large health pool,
  no spawns within 300 yards of Northshire; seeded at spawn guid 9990005, `(-8949.95, -128.5, 83.5312)`.
  It never retaliates, so the mage stays out of combat after the cast.
- `character_spell` is **empty on purpose**: `Player::LoadFromDB` calls `LearnDefaultSkills()` before loading
  spells, so starting spells are re-granted at every login and only trainer-learned spells persist (compare
  Plan 34's Battle Shout row). The persisted witness here is `character_action`, and the behavioural witness
  is the second cast after the relog.
